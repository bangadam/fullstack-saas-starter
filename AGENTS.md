# AGENTS.md — AI agent operating guide

This repo is a Cloudflare-native SaaS boilerplate (TanStack Start + Hono + D1/R2/Queues, pnpm monorepo). Work here in small, verified steps: write or update tests first (TDD), then code, then run the gate checks.

## Golden commands (run from repo root)

```bash
pnpm install            # dependencies (Node >= 22, pnpm via corepack)
pnpm wizard --yes       # generate saas.config.ts + .env.local (gitignored)
pnpm bootstrap          # .dev.vars + local D1 migrate + seed (idempotent)
pnpm dev                # web + api + jobs; web on http://localhost:3000
pnpm test               # vitest across the workspace (turbo)
pnpm typecheck           # tsc everywhere
pnpm lint               # biome
pnpm check              # CLI doctor: node/pnpm/config/dev-vars/db/billing/auth
pnpm scan:secrets       # scan git-tracked files for committed credentials
pnpm smoke              # HTTP smoke test, needs `pnpm dev` running
pnpm stop / pnpm restart
```

Notes: `pnpm doctor` and `pnpm setup` are **pnpm builtins** — they never reach this repo. Ours are `pnpm check` (doctor) and `pnpm wizard` (setup wizard). Interactive test flows live in `apps/web/e2e/flows.mjs` — they are agent-driven (browser bridge), not CI; CI coverage is `pnpm smoke` + vitest.

## Request flow

Browser → Web Worker (`/api/*` and `/webhooks/*` forwarded over a service binding, **path unchanged** — public path equals internal path) → API Worker (Better Auth at `/api/auth/*` → `requireSession` → domain services → D1; auth emails go through the `email_outbox` + Queue; webhooks verified on raw body) → Jobs Worker (Queues consumer, Cron). Payment providers and browser R2 PUTs hit the Web Worker only.

## Invariants you must not break

1. **Routing contract** (`apps/api/src/index.ts` header, `apps/web/src/lib/proxy.ts`, `docs/architecture.md`): the proxy forwards `/api/*` **verbatim** and the API Worker serves everything under `/api/*`; Better Auth basePath is `/api/auth`. Never re-add prefix stripping: Better Auth builds email links and OAuth callbacks from its basePath, and a stripped prefix produced `/auth/reset-password/<token>` links that 404. `apps/web/src/lib/proxy.test.ts` guards this.
2. **D1 has no interactive transactions.** Enforce quotas/tenant rules with conditional writes (`INSERT … SELECT … WHERE count < limit`) or atomic `batch`. Never read-then-insert as enforcement.
3. **Tenant scoping is by `userId` on every read/write** (B2C model; organizations were deliberately removed — see ADR note in `docs/extending.md`). New tables must carry non-null `user_id` with an index; domain methods take `userId` first.
4. **TanStack Start import protection**: `@tanstack/react-start/server` is server-only and mocked in the client bundle. Use `typeof window === 'undefined'` to gate server-only code (see `dashboard.tsx` gate), never import `isServer` from `@tanstack/react-router` (it is not exported there).
5. **Secrets live only in the worker that uses them** (`.dev.vars`, gitignored; never in web/public vars). Never log secrets, cookies, bodies, or webhook payloads. Use `redactSecrets` for config output. Run `pnpm scan:secrets` before committing (also a CI gate). If you ever find a real credential in a tracked file: redact first, then tell the user to rotate it — the value is already in git history.
6. **Pros/cons of fetch in web**: SSR path must forward the caller's cookie + origin (workerd cannot resolve relative URLs); client path uses relative same-origin fetch and lets cookies ride along.
7. **Webhooks verify signatures on the raw body first**, persist the event (durable), then ack; replays must be idempotent (see `billing_events` dedup key).
8. **At-least-once queues**: every job payload carries a jobId/idempotency key; side effects are check-and-write atomic in D1 before execution; failures beyond retry go to the DLQ.
9. **Plan entitlements** (`@saas/billing` `PLAN_ENTITLEMENTS`) decide limits; `maxProjectsForUser` and `storageLimitForUser` resolve the plan per request from the newest subscription row (active/trialing = pro, everything else = free). Never hardcode caps in services — inject them.
10. **Turbo cache/logs are gitignored** — never commit `.turbo` or `.wrangler`.
11. **Auth lifecycle flows**: password reset (`/forgot-password` → `POST /api/auth/request-password-reset` → email link → `GET /api/auth/reset-password/:token` → `/reset-password?token=…` → `POST /api/auth/reset-password`) and email verification (`/verify-email`, resend from Settings → `POST /api/auth/send-verification-email`). Emails are dispatched through `EmailOutboxService` (durable row first, then queue) — never send inline from a request.
12. **Storage quota is enforced before an upload URL is handed out** (`storageQuotaDecision` from `@saas/domain` against `PLAN_ENTITLEMENTS.maxStorageBytes` and the user's `SUM(files.size)`) → 402 `QUOTA_EXCEEDED`. Uploads are two-step: authorize (metadata row written) then PUT the bytes — presigned R2 when `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`CLOUDFLARE_ACCOUNT_ID` are set, otherwise a same-origin `PUT /api/files/upload/:id` that writes through the R2 binding, so local dev works without S3 keys.
13. **Request guards in the API Worker are non-negotiable**: `originGuard` (CSRF — cookie writes need an allowed Origin; `/webhooks/*` exempt via signature), `rateLimitGuard` (D1-backed, bucketed by client identity; env overrides `RATE_LIMIT_AUTH_STRICT|WRITE|WEBHOOKS` as `limit/windowSeconds`), and `turnstileGuard` on credential paths (fail-closed when a secret is set; token arrives on the `cf-turnstile-response` header). `services` depending on D1 must be registered before the rate limiter in `createApp`.

## Working conventions

- TDD for every behavior change: add/adjust a failing test in the owning package (`*.test.ts`, vitest), implement, then `pnpm test` + `pnpm typecheck` + `pnpm lint` for touched areas.
- Adding a domain module: contract (zod) → `packages/db` schema + migration (review SQL) → `packages/domain` service + port + adapter + tests → route behind `requireSession` → SDK method → web hook/page. Full recipe in `docs/extending.md`.
- Browser UI copy stays in `apps/web`; shared primitives only in `packages/ui`.
- Prefer the SDK client in web code over raw fetch; prefer `~/lib/auth-client.ts` for sign in/up/out.
- After UI route changes, verify the SSR branch *and* the client-navigation branch in a real browser: full reload + click-through (these diverge — see invariant 4).
